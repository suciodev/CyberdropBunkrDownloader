# CyberdropBunkrDownloader

Download files from [Bunkr](https://bunkr.cr) and [Cyberdrop](https://cyberdrop.me) albums.

## Install

```bash
# Requires Python 3.12+ and uv
uv sync
```

## Quick start

```bash
# Download a single album
uv run cyberdrop download -u https://bunkr.cr/a/XXXXXXXX

# Batch-download from your bookmarks.yml
uv run cyberdrop bookmarks

# See all commands
uv run cyberdrop --help
```

## Commands

### `cyberdrop download` — single album or file list

```
cyberdrop download -u URL                     # one album/file URL
cyberdrop download -f urls.txt                # file of URLs (one per line)
  -e jpg,mp4          only download these extensions
  -p ./my_dir         custom output directory (default: downloads/)
  -w                  write URL list instead of downloading (for wget etc.)
  --before DATETIME   only files uploaded before this date (YYYY-MM-DDTHH:MM:SS)
  --after  DATETIME   only files uploaded after this date
```

### `cyberdrop bookmarks` — batch download from bookmarks.yml

```
cyberdrop bookmarks
  -b bookmarks.yml    bookmarks file path (default: bookmarks.yml)
  -c Creator1 ...     download only these creator(s)
  -e jpg,mp4          filter extensions
  -o downloads        output staging directory
  --skip-downloaded   skip links already marked as downloaded
  --no-update         don't write download status back to bookmarks.yml
  --consolidate       move files to consolidation_path after downloading
```

### `cyberdrop import` — add URLs to bookmarks.yml

```
cyberdrop import -c "CreatorName"
```

Reads URLs from stdin (one per line). Each URL is added under the creator with an
auto-generated name (`CreatorName 1`, `CreatorName 2`, …). Press **Ctrl+Z+Enter**
(Windows) or **Ctrl+D** (Mac/Linux) when done.

### `cyberdrop consolidate` — move files to their final destination

```
cyberdrop consolidate
  -c Creator1 ...     consolidate only these creator(s)
  -o downloads        staging directory to move from
```

Moves files from the `downloads/` staging folder into each creator's
`consolidation_path` (defined in `bookmarks.yml`). Handles duplicate filenames
automatically by appending `_1`, `_2`, etc.

## bookmarks.yml

Copy `bookmarks.example.yml` to `bookmarks.yml` and fill in your own entries.
`bookmarks.yml` is gitignored so your personal links stay local.

```yaml
creators:
  - name: ExampleCreator
    consolidation_path: /path/to/final/destination   # optional
    links:
      - name: "Pack 1"
        url: https://bunkr.cr/a/XXXXXXXX
        downloaded: false
```

**Key fields:**

| Field | Required | Notes |
|-------|----------|-------|
| `creators[].name` | yes | Used for creator filtering (`-c`) and fuzzy folder matching |
| `creators[].consolidation_path` | no | Final destination; files are moved here by `--consolidate` |
| `links[].name` | yes | Album label; used by fuzzy matching during consolidation |
| `links[].url` | yes | Bunkr or Cyberdrop album/file URL |
| `links[].downloaded` | auto | Set to `true` after a successful download; reset to `false` to re-download |

**Tips:**
- `links[].name` doubles as a folder-match hint for consolidation. The name you give a link
  is compared (case-insensitively, special-chars stripped) against folder names in `downloads/`.
  Names generated by `cyberdrop import` include the creator name (`CreatorName 1`) which
  helps the fuzzy match find the right folder automatically.
- Both `bunkr.cr/a/…` (album), `bunkr.cr/f/…` (single file), and `cyberdrop.me/a/…` URLs work.
- Minimal format: links can be plain URL strings instead of dicts — they'll be normalised automatically.

## Examples

`run_example.sh` contains ready-to-run examples for every command. Edit the URLs and creator
names at the top, then:

```bash
bash run_example.sh
```
